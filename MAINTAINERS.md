## Contact

Use repository issues and pull requests for ordinary project work, and mention an active maintainer when attention is needed. Do not send vulnerability details through a public issue or an unverified address; follow [SECURITY.md](SECURITY.md). For a sensitive conduct concern, follow [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

The project does not publish a general private contact address. Where a policy calls for a private channel and GitHub does not provide one directly, ask a listed maintainer to establish one without disclosing sensitive details publicly.

## Status and updates

Maintainer responsibilities, nominations, recusals, inactivity, and removal are defined in [GOVERNANCE.md](GOVERNANCE.md). Changes to this list require the public process specified there. Repository permissions and CODEOWNERS entries are operational controls and do not replace this list.
